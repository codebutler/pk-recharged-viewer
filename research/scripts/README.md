# Dumped event scripts — Pokémon Recharged Yellow

Generated by `research/tools/dump_scripts.py` from `local/Pokemon Recharged
Yellow.gba`. Regenerate with:

```sh
python3 research/tools/dump_scripts.py
```

Everything here is derived from the ROM, so it describes **this hack**, not
vanilla Emerald or FRLG. Answer gameplay questions by grepping this tree rather
than reasoning from vanilla games — that is the whole point of it existing.

## Layout

| Path | What it is |
|---|---|
| `maps/gNN_mMM_<Name>.txt` | One file per map. Every script entry point (object events, signs, coord triggers, map-script tables), disassembled with dialogue inlined and item/flag/var names resolved. |
| `index/item-sources.json` | item name → every place it can be obtained |
| `index/marts.json` | map → the list of items that mart sells |
| `index/stats.json` | coverage counts, stop reasons, unresolved opcodes |

## Typical queries

```sh
# where do I get X?
python3 -c "import json;print(json.load(open('research/scripts/index/item-sources.json'))['Rare Candy'])"

# what gates this NPC / what reads this var?
grep -rn "0x405D" research/scripts/maps/

# what does this map contain?
less research/scripts/maps/g03_m06_Celadon_City.txt
```

## Confidence

**Coverage: 8493 of 8880 scripts (95.6%) decode to a clean terminator**, across
491 maps. The other 35 of the ROM's 526 maps have no scripts at all — only
warps, with empty map-script tables (verified, not assumed).

Reachability: every map's object events, signs, coord triggers and map-script
tables are entry points, and the walk follows goto/call/goto_if chains plus the
post-battle CONTINUE_SCRIPT pointer of `trainerbattle` (its other pointers are
text and are deliberately not decoded as code). The walk is a worklist with no
depth cap.

The opcode table is derived in `research/script-opcodes.json` from two
independent readings of the vendored pokeemerald sources (the assembler macros
in `asm/macros/event.inc` and the C handlers in `src/scrcmd.c`), which agree on
223 of 227 vanilla opcodes. It is then overlaid with **this ROM's own command
table** at 0x081F1630 (235 entries), so opcodes the hack stubbed out decode as
nops and opcodes the hack reimplemented are not decoded with vanilla widths.

Verified: the decoder reproduces the independently hand-decoded Game Corner
grunt script at 0x08266562 (gated on var 0x405D ≥ 2) exactly — see
`research/hack-offsets.md`.

### Known gaps — read before trusting a negative result

- **Five opcodes are unresolved: 0xE3, 0xE4, 0xE5, 0xE7, 0xE9.** They are hack
  customs whose argument widths could not be established. Empirical length
  fitting was flat for all five (margin 0–5 scripts, i.e. noise) and the handler
  disassembly estimates were not corroborated, so they deliberately **stop**
  their script rather than risk decoding everything after them at the wrong
  offset. ~190 scripts truncate on these. Two customs *are* resolved: 0xE6
  (multi-language msgbox, 7 text pointers) and 0xE8 (speaker name).
- 0xC7 `textcolor` (length 2) and 0xD0 `setworldmapflag` (length 3) were
  recovered from this ROM and then **confirmed against `vendor/pokefirered`**,
  whose macros and command table give the same opcode numbers and argument
  widths. See the evidence comments on `RESOLVED_SIGS` in `dump_scripts.py`.
- **`vendor/pokefirered` is genuinely useful here**, despite CLAUDE.md having
  long dismissed it as a dead end. This hack is FRLG content on the Emerald
  engine, so for commands Emerald stubbed out but FRLG implements, pokefirered
  is the correct reference. Check it before treating an opcode as unknowable.
- ~140 scripts stop with `opcode-out-of-range`, which usually means a pointer
  led into text or data rather than code. Harmless, but it means a script may be
  incompletely rendered.
- **Not yet dumped:** trainer parties, wild encounter tables, and the Game
  Corner prize list. So "no mart sells X" does **not** rule out the Game Corner.
  Item sources cover mart stock, ground item balls, hidden items, and scripted
  gives.
- **Standard scripts are not dumped.** There are 3680 `callstd`/`gotostd`
  references into the shared `gStdScripts` table, which is not located or
  rendered here. The calls appear in the dump as `callstd function=N`; what
  script N runs is not shown. Item-giving standards (0 and 1) are decoded
  semantically, so item sources are unaffected.
- Not covered at all: battle scripts, and the custom "Smsh" achievement VM
  (different bytecode — see `research/hack-offsets.md`).
- Item balls are detected by the `setorcopyvar VAR_0x8000, <item>` +
  `callstd 0/1` idiom. A gift using some other idiom would be missed.
- **Text**: the 0xFC extended-control-code argument counts are transcribed from
  `sExtCtrlCodeLengths` in pokeemerald's `src/string_util.c`, and an unrecognized
  control code truncates that string rather than guessing. Text fidelity has been
  eyeballed, not diffed at scale against a known-good corpus.
- **`msgbox_multilang` (0xE6) slots are numbered, not named.** Slot 0 is English;
  slot 1 was observed holding Spanish, so the slot→language order is unverified.
  Do not assume `text_1` is any particular language without checking SB2+0x91.
